# Hexblast 关卡设计 — 六图五章（地图 × 章节双层结构）

> 文档定位：关卡结构设计提案（v5），仅作实现基线，本轮不修改代码或资源。
>
> 设计版本：2026-10-09 v5（讨论定稿）。v5 相对 v4（2026-10-03《关卡设计-15波.md》）的核心改动：
> 1. **结构分层**：原 6 个"章"升级为 6 张**地图**（环境 + 怪物身份层），每图下设 5 个**章节**（推进层），全游戏 30 个通关节点；
> 2. **一局一章不变**：每局仍只打选定章节的 15 波，图内 5 章是 5 次独立 run，不连续；
> 3. **解锁链**：全局 30 节点严格线性，图 N+1 需图 N 五章全通；已通内容自由重打；
> 4. **UI 新增图内章节选择页**，选图页改造，硬性无重叠/遮掩验收标准（见 7.4）；
> 5. **新增任务线最小系统**：每章 = 一个任务节点（见 8）。
>
> 难度体系不在本轮改动：维持"每局选"（选章后、选英雄前），四档全开放，与图/章正交；五档难度提案另行确认。

## 1. 设计目标：为什么要拆两层

v4 的"章"同时承担**环境身份**（背景/场地/怪池/小首领/Boss）与**推进节点**（数值档/解锁链）两个职责。内容想从 6 关扩到 30 关时，每关都要一套全新环境素材与怪池，美术和平衡成本爆炸。v5 把两个职责拆开：

- **地图层（6 份，固定身份）**：背景、场地碰撞布局、近战/远程怪池全集、小首领池、图末大 Boss、BGM、主题色。现 6 章的环境包原样升级为 6 图，美术零新增。
- **章节层（30 份，推进节点）**：任务线文案与奖励、数值档（statScale/countScale）、图内怪池渐进（每章解锁新怪进池）、本章固定变异、关底配置、开局战备包。

| 目标 | 量化指标 |
|---|---|
| 一局时长 | 不变：8~10 分钟，硬上限 12 分钟 |
| 首通全内容 | 30 局（v4 为 6 局），平均每图 5 局 |
| 图内章间差异 | 每章至少 1 个新怪 + 1 组固定变异 + 不同关底组合 |
| 重打价值 | 已通图/章自由重打（刷装备/任务/核心币），与现行为一致 |

## 2. 层级模型与数据结构

### 2.1 全局章号（唯一真源）

- 全局章号 `k ∈ 1~30`；图号 `m = ceil(k/5)`；图内章 `c = ((k-1) % 5) + 1`。
- 新增 `data/LevelIndex.ts`：`MAPS: MapDef[6]`，每图持 `chapters: ChapterDef[5]`；导出 `globalChapter(m, c)` / `mapOf(k)` / `chapterInMap(k)` / `TOTAL_CHAPTERS = 30`。
- **规范**：存档、解锁、成就、进度统计只用全局章号；UI 显示"图 m-c"；全链路统一 1-based（顺手消灭现状 0/1-based 三种表示混用的技术债）。

### 2.2 MapDef（地图层字段）

| 字段 | 来源 | 说明 |
|---|---|---|
| id / name / bgKey | 现 `WaveData.CHAPTERS` | 原章名/bgKey 原样升级 |
| arenaRef | 现 `ChapterArenaDB` | 按 `Record<1..6>` 改按 mapId 查询；每图 2 布局 + 15 候选槽不变 |
| meleePool / rangedPool / miniPool | 现 `WaveManager._meleePool/_rangedPool/MINI_POOL` 上移 | 环境身份归数据层，WaveManager 只消费 |
| bossId | 现 `BossDB.BOSSES` | **改为显式 id 查表**，废弃按下标对齐章节的取法（现状易错位） |
| bgmKey / accent / tone | 现散落数组（`_chapterBgm`、选图卡 6 色、`_applyBackgroundTone`） | 收敛进 MapDef |
| arcIntro / arcOutro | 新增 | 图级剧情弧线文案（图终剧情用，见 8） |

### 2.3 ChapterDef（章节层字段）

| 字段 | 说明 |
|---|---|
| mapId / index | 图号与图内章号（1~5） |
| name / statScale / countScale | 沿用 v4 双轴，曲线重拉 30 档（6.1） |
| unlockAdds: string[] | 本章新解锁进图池的怪（渐进，见 5.2） |
| mutations: string[] | 本章固定变异（复用现 `MUTATIONS` 10 种，见 5.3） |
| finale | 前 4 章 = 小首领关底组合；第 5 章 = 图末大 Boss（见 5.1） |
| quest: { title, desc, intro, outro, reward, challenges? } | 任务线节点：任务 + 剧情引子/尾声 + 可选挑战星（见 8） |
| starter: { draws, gold } | 开局战备包，30 档（见 6.2） |

## 3. 解锁与重打

- 解锁链：通关全局第 k 节点解锁第 k+1 节点；第 1 节点默认解锁。
- **图 N+1 的第一章 = 全局 5N+1 节点**，排在线性链上"图 N 章 5"之后 → 地图挨个解锁自动成立，**不需要图级独立解锁字段**。
- 已通内容自由重打：解锁数 = 已通关数 + 1，之内的任意图/章随便选（沿用现选章页行为）。
- 存档：`PlayerProfile.chaptersCleared` 语义从 1~6 扩为 1~30；`unlockedChapterCount() = min(30, cleared + 1)`。

## 6. 数值曲线（30 档基线，实测按"图 m 章 c 首通成功率 40~60%"校准）

### 6.1 statScale / countScale（线性）

公式：`stat(k) = 1 + (k-1)×3.2/29`（1.00→4.20）；`count(k) = 1 + (k-1)×1.2/29`（1.00→2.21）。

| 图 | 章1 stat/count | 章5 stat/count |
|---|---|---|
| 1 | 1.00 / 1.00 | 1.44 / 1.17 |
| 2 | 1.55 / 1.21 | 1.99 / 1.37 |
| 3 | 2.10 / 1.41 | 2.55 / 1.58 |
| 4 | 2.66 / 1.62 | 3.10 / 1.79 |
| 5 | 3.21 / 1.83 | 3.66 / 2.00 |
| 6 | 3.76 / 2.04 | **4.20 / 2.21** |

对照 v4：旧第 6 章 2.3/2.0 → 新终节点 4.2/2.2，强度增量由战备包加陡补偿（6.2）。

### 6.2 开局战备包 30 档

公式：`draws(k) = round((k-1)×14/29)`（0→14）；`gold(k) = round((k-1)×900/29 /10)×10`（0→900）。锚点：

|---|---:|---:|
| 图1章1 | 0 | 0 |
| 图1章5 | 2 | 120 |
| 图2章5 | 4 | 280 |
| 图3章5 | 7 | 430 |
| 图4章5 | 9 | 590 |
| 图5章5 | 12 | 740 |
| 图6章5 | 14 | 900 |

（v4 端点 10 抽/700 金 → 14 抽/900 金，对应 30 章更长的成长轴；占位待校准。）

### 6.3 金币与装备

- `GOLD_STAGE_MULT`（Economy.ts）6 档 → 30 档：按 v4 锚定法（图 1 章 1 普通 ≈1600 金/局）随 countScale 线性抬升，图 6 章 5 目标 ≈2600 金（占位）。
- 装备品质 cap 按图分档（对齐现体验位置）：图 1→0 档，图 2~3→1 档，图 4~6→2 档；分界待校准。
- 核心币折算 `min(80, gold×0.2)` 不变——上限 80 自然防高图通胀。

### 6.4 数量封顶复核

`ENEMY_COUNT_CAP = 128`。图 6 章 5 W13 兽潮：`41.2 × 1.45 × 2.21 × 1.2(地狱) ≈ 159` → 恒顶满 128（v4 图 6 已 ≈120）。影响：终盘密度不再随难度增长、只涨数值，可接受；若试玩觉得地狱档后期不够挤，cap 提 144 并做性能实测，另议。

### 7.4 硬性验收标准（防重叠/遮掩，实现与验收都按此过）

1. **相邻卡边缘净间距 ≥ 18px**：点击热区不得重叠。Cocos 2D 后创建节点渲染在上层、其 UITransform 热区会盖住先创建卡的可见区域——这是现选图页注释里踩过的坑（间距公式：`间距 = 卡中心距 − 卡宽`；3+2 布置为 380−300=80px ✓）。
2. **页面纵向分带互斥**：标题带 y ≥ 240 / 卡片区 −250~+200 / 底部提示条 y ≤ −280；任何元素不得跨带。
3. **卡内文字零溢出**：所有 Label 用 `Overflow.SHRINK` + 固定行高，长文案缩字号不溢出卡边界；卡背景 Graphics 尺寸 = UITransform 尺寸。
4. **高亮/选中态不用缩放**，用描边与亮度变化（缩放会吃掉卡间距）。
5. **布局常量集中定义**（卡片宽高/行 y/列 x 数组），改卡尺寸必须同步重算间距，选图页与章节页共用同一套校验。

### 7.5 HUD 与结算文案

- 战斗 HUD：`第X章` → `图m-c · 第w波（w/15）`。
- 通关结算：`图m 第c章 肃清`；终局（全局 30 节点全通）沿用"终局达成！"分支，`finalChapter` 改按全局章号判断。

## 8. 任务线系统（章节驱动剧情推进）

设计原则：**章节是任务线的唯一推进器**——通关即推进，不通关不推进；任务线不设关卡之外的独立玩法闭环（不做日常/周常）。三层结构：

| 层 | 内容 | 触发 |
|---|---|---|
| 主线剧情 | 每章 `intro`（章前引子）+ `outro`（首通剧情）；图末章通关追加**图终剧情**（本图弧线收尾 + 下张图预告） | 通关该章 |
| 章节任务 | 每章一个任务节点（title/desc + 首通奖励） | 通关该章 W15，任意难度有效 |
| 可选挑战 | 每章 1~2 个挑战星（额外奖励，非门槛，不挡解锁） | 局内达成即记录，重打可补 |

### 8.1 剧情展示节点

- **开战前引子**：首次进入该章，W1 前显示剧情横幅（点击跳过）；重打不再弹。
- **通关结算剧情**：结算面板追加剧情段落——首通显示完整 outro，重打显示一行简版。
- **图全通**：图终剧情 + 选图卡"✓ 已肃清"徽章 + 下张图解锁提示。
- **章节页任务线一览**：页顶 5 节点连线，已通节点点亮、当前节点高亮——"章节推动任务线"的可视化主体。
- 大厅剧情回顾页：复用现 MetaProgressionDB 页面骨架（现为占位数据，正好接活），第二期再接。

### 8.2 可选挑战（挑战星）

- 挑战条件从**现有统计白名单**里选，不为任务系统改战斗内核：用时、击杀数、金币结余、连击峰值（bestCombo 已存档）、是否进过商店。
- 示例：图1章2"8 分钟内通关"、图2章3"击杀 ≥ 220"。
- 达成即时写入存档，与首通无关；集满一图 5 章全部挑战 → 额外装备箱。

### 8.3 数据与存档

- `ChapterDef.quest` 扩展为 `{ title, desc, intro, outro, reward, challenges?: [{ id, desc, goal }] }`；`MapDef` 增 `arcIntro / arcOutro`。
- 剧情与任务进度**直接复用 `chaptersCleared` 线性链**，不新增推进字段；仅新增 `questStars: Record<number, string[]>`（全局章号 → 已完成挑战 id）。
- 成就挂点："任务线全通（30/30）"、"单图满星"。

### 8.4 第一版明确不做

支线 NPC、跨章连锁任务、难度条件挑战、剧情回放、语音。
