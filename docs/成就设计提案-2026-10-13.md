## 2. 设计原则

1. **先类型、后等级**（v2 定稿）：类型（挑战/探索/收集）是一级分组，决定页签与浏览动线；稀有度（等级）只在类型内部排序，是"同类型里的达成难度梯度"，不再跨类型比较。
2. **不推翻已解锁记录**：现有 13 个成就的 `id` 全部保留，只修 progress 语义与个别分档；玩家已解锁的不回收。
3. **只用已有统计数据**：成就判定只读 `PlayerProfile` 已有字段（与任务线挑战星同一原则），不为成就改战斗内核；个别新挂点用已有 `RunSummary` 字段即可覆盖。
4. **奖励落地但克制**：核心币类奖励真发（直接入 `coreCoins`）；称号/档案框类仅作展示预期，不新增系统。
5. **稀有度 = 类型内特殊性**：普通（顺手解锁）→ 稀有（稳定投入）→ 史诗（明确目标）→ 传奇（类型内顶级/极限）。

## 4. 奖励发放规则

- `AchievementDef` 增加 `rewardCoins?: number`；`SaveSystem.checkAchievements()` 判定解锁时立即 `p.coreCoins += rewardCoins`（与解锁同帧入档，天然防重复发）。
- **存量补偿**：提案 A——已解锁条目不补发（简单，防刷）；提案 B——迁移时按已解锁一次性补发 coreCoins（对老玩家友好）。**默认按 A**，确认时可改。
- 页面去掉"奖励为预览"标注。

## 5. 页面改造（成就档案库）——先类型、后等级

1. **一级分组 = 类型页签**：挑战 / 探索 / 收集 三个页签（复用图鉴页按钮样式），页签带"已解锁/总数"角标（如 `挑战 3/10`）；默认进入第一个页签。顶部摘要行显示全局进度（已解锁 x / 24）。
2. **二级排序 = 等级**：类型内按 普通→稀有→史诗→传奇 排列；等级之间加细分隔行（等级名 + 主题色短横），滚动容器内整体下翻。排序键 = 类型 + 等级 + 定义顺序，与达成状态无关——解锁新成就不会引起卡片跳动。
3. **已达成的卡片**金色高亮（现状保持）；隐藏成就未解锁仍以"？？？"遮掩。
4. **解锁反馈**：结算面板（gameover / chapterClear）底部新增一行"本局新解锁：xxx、xxx"（数据已有，`_recordRun` 返回的 `unlocked` 目前只弹浮动字）；大厅入口红点不做（奖励即时发放，无"领取"步骤）。
5. 原顶部的稀有度图例移入滚动区首行说明或页签旁，避免与类型页签争夺视觉层级。
