# 存档服务器提案（2026-10-20，方案 B：本机 Node 存档服务器）

> 状态：**待确认**（文档先行，确认后再实施）。
> 目标：存档**入库**并绑定**登录账号**——账号在本机 Node 服务器注册登录，档案随账号走（换浏览器/换设备登录同一账号即恢复）；**后期整体迁移到云 BaaS** 时 API 契约不变，只换部署位置与登录方式。
> 已按玩家指示移除档案列表页的存档码导出/导入入口（数据层函数保留备用）。

## 1. 总体架构

```
server/                       新增目录（独立 Node 进程，与游戏客户端解耦）
  server.mjs                  零依赖纯 Node http 服务（无需 npm install，node server.mjs 即跑）
  data/
    accounts/<账号id>.json    账号：account/passwordHash/scrypt盐/createdAt/token
    saves/<账号id>.json       该账号的 3 个档案槽（PlayerProfile JSON 原样）+ updatedAt
  LAN 访问：http://<本机局域网IP>:7460（手机/平板同 WiFi 直接玩）

客户端（Cocos web）
  启动 → 登录页（新） → 登录成功拉取账号档案 → 菜单/大厅照常
  游玩期间档案写入 = 本地照旧 + 异步 POST 镜像到服务器（见第 4 节）
```

- **零依赖**：纯 Node 内置模块（http/crypto/fs），不用 Express/数据库软件——拷个目录就能跑，后期迁云时把存储换成 BaaS SDK 即可。
- **端口 7460**（避开游戏预览的 7456），可在 server 顶部配置。

## 2. 登录方式（本机阶段的现实约束）

- **账号 = 手机号或自定义昵称 + 密码**。本机/局域网服务器没有短信网关和微信开放平台资质，做不了真·验证码/微信 OAuth——**第一阶段用"账号+密码"**，数据模型预留 `wechatOpenId` 字段，迁云 BaaS 后可绑定真微信登录。
- 登录成功签发 **token**（随机串，存服务器 + 客户端 localStorage），**7 天免登录**，过期重新输密码。
- 密码绝不明文存：scrypt（Node 内置 crypto）加盐哈希。

## 3. 数据模型与 API

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/register` | POST | `{account, password}` → 建号，返回 `{token, profiles}` |
| `/api/login` | POST | 同上（校验密码），返回 `{token, profiles}` |
| `/api/profiles` | GET | Bearer token → 该账号全部 3 档案槽 + 各槽 updatedAt |
| `/api/profiles/:slot` | POST | Bearer token + PlayerProfile JSON → 保存该槽（含 updatedAt） |
| `/api/logout` | POST | 吊销 token |

- **档案内容原样存储**：客户端 `PlayerProfile` JSON 直接落盘（含 `chaptersCleared/bestChapter/achievements/...` 全部字段），服务器不理解字段含义——客户端版本升级新增字段天然兼容。
- **冲突策略：last-write-wins**（每次保存带 updatedAt，直接覆盖）。限制：**同一账号同一时间只在一台设备玩**（家庭场景足够；提案确认后写进登录提示）。

## 4. 客户端改造（关键点：游戏内核零改动）

现状：`SaveSystem` 全同步读写 localStorage。改造成 server-authoritative 需要把全部读写异步化——牵动太大。因此采用**镜像同步**方案：

1. **登录页**（新增 `ScreenName 'login'`，启动即显示，在菜单之前）：
   - 输入账号/密码 → 注册或登录；
   - **「游客离线」按钮**：跳过登录，纯本地玩（不登录也能玩，档案不上云）；
   - 登录成功 → 从服务器拉取该账号 3 槽档案 → **覆盖写入本地 localStorage** → 进首页。
2. **游玩期间**：`SaveSystem.save()` 保持本地写入不变，同时在有 token 时**异步 POST 该槽到服务器**（失败不阻塞游戏，顶部浮字提示"存档同步失败"并稍后重试）。
3. **效果**：换浏览器/换设备（手机）→ 打开游戏 → 登录同一账号 → 档案自动恢复。游戏内所有系统（GameManager/成就/后台管理）零改动。
4. 档案列表页（大厅内切换档案）UI 不变；登录后它展示的就是服务器拉下来的账号档案。

## 5. 安全与边界

- 局域网内明文 HTTP（家庭网络可接受）；密码 scrypt 加盐；token 7 天过期。
- 服务器只监听局域网，不暴露公网；迁云时在云端加 HTTPS。
- 本机服务器**关机即不可用**：客户端检测不到服务器时自动回退离线模式（可玩，进度本地留存，下次登录同账号会以本地较新数据覆盖服务器——按 updatedAt 策略）。

## 6. 云 BaaS 迁移预留

- API 路径/请求体/档案 JSON 结构即契约；迁云 = 把 `server.mjs` 的存储/鉴权换成 BaaS（如 LeanCloud/云函数），客户端只改 baseUrl（配置项 `server/CONFIG` + 客户端常量各一处）。
- `wechatOpenId` 字段已预留，届时接微信登录。
