# Hexblast 专业化视觉与听觉优化方案（2026-08-20）

## 0. 目标与判断标准

本方案不是“继续堆高清图片”，而是建立一套可持续生产、在实机中保持一致的美术系统。目标是消除素材拼装型网页游戏观感，使画面达到成熟商业独立游戏的完整度。

最终判断不看单张原画，而看以下五个结果：

1. 不带 Logo 的战斗截图也能被识别为同一款游戏。
2. 玩家、敌人、危险、奖励在 0.5 秒内完成信息分层。
3. UI、角色、场景、特效、音频使用同一套形状和材质语言。
4. 64px 实际战斗尺寸下仍能看清角色职业、朝向和主要武器。
5. 所有反馈都具有“前摇—爆发—收尾”，而不是图片突然出现后线性消失。

## 1. 统一美术方向

推荐方向：**暗色工业奇幻 + 手绘科幻 + 克制霓虹的 2.5D 俯视风格**。

### 1.1 形状语言

- 六边形只用于能量、技能、稀有度和关键交互，不作为无意义满屏装饰。
- 玩家：稳定、向外展开的轮廓，武器方向明确。
- 普通怪：尖锐和前倾；坦克怪：方形和低重心；远程怪：细长；爆炸怪：圆形膨胀。
- UI：斜切角金属框、两侧短能量槽、上沿高光、下沿暗边。
- 禁止：普通功能按钮使用无边框纯色矩形；战斗角色使用胸像徽章；用 Emoji 充当正式图标。

### 1.2 色彩比例

- 70%：炭黑、深海军蓝、暗钢灰等中性色。
- 20%：章节主题色。
- 10%：玩家技能、危险警告和奖励高亮。
- 青色用于玩家/交互，红橙用于危险，金色用于奖励与高稀有度，绿色用于治疗，黄绿色用于毒。
- 同一时间同一区域最多保留两个高饱和焦点。

### 1.3 光照与材质

- 所有战斗角色统一左上主光、右下接触阴影。
- 金属为暗哑磨损，不使用大面积镜面高光。
- 能量仅在核心、武器口、技能纹路发光，不给整个角色描一圈高亮霓虹。
- 场景中央战斗区保持低频和低对比，建筑、裂缝和故事物件集中到边缘。

## 2. 页面按钮重构

### 2.1 当前根因

- 多数按钮由 `Graphics.fillRect()` 直接画纯色矩形，只有一圈细描边。
- 首页按钮曾烧录进 `title_screen.png`，可见位置、点击热区和功能状态无法同步。
- 不同页面的按钮高度、颜色、描边、文字大小和禁用状态缺乏统一规范。

### 2.2 已落地方案

- 新增 `core/UIStyle.ts` 作为代码原生按钮皮肤。
- 按钮采用斜切角金属底板、独立投影、双层填充、上沿高光、下沿暗边和两侧能量槽。
- 支持 `normal / hover / pressed / disabled` 四态：
  - hover：轮廓提亮、整体放大 2.5%。
  - pressed：整体压缩至 97.5%，内层颜色变暗。
  - disabled：降低饱和度和对比，不响应业务点击。
- 首页背景图已重绘并移除全部烧录按钮；真实按钮直接叠在城市负空间上，不再使用遮挡背景的深色操作台。
- 角色名牌、重试、返回主菜单、继续、暂停恢复、商店购买/离开、强化跳过统一使用同一组件。

### 2.3 下一阶段

- 将设置、图鉴、升级等功能上线时直接复用 `applyHexButtonSkin()`，不再向背景图写文字。
- 增加键盘/手柄焦点态：外框 2Hz 呼吸、左侧显示焦点箭头。
- 所有按钮文字使用单行缩放，禁止因为宽度不足自动换成两行。

### 2.4 验收

- 可见轮廓和 `UITransform` 点击区域完全一致。
- 鼠标、触摸、键盘/手柄都能看到明确状态变化。
- 截图转灰度后，按钮仍能通过边框和明暗分辨主次。
- 禁用按钮不可触发回调，且视觉上不冒充可用功能。

## 3. 英雄战斗形象重构

### 3.1 当前根因

原 `char_token_*` 中五名角色是正面胸像徽章，Liana 是高细节写实半身立绘。缩到 60px 后没有脚、方向和重心，角色像贴纸在地面滑动，六名英雄也不属于同一种画法。

### 3.2 已落地方案

- 六名英雄全部替换为 512×512 透明 PNG、3/4 俯视、脚部可见的全身战斗 Sprite。
- 统一为暗色工业奇幻手绘 2.5D 风格，并保持各职业武器和身份色：
  - Kai：青色双管能量枪手。
  - Vivian：蓝色工程师与悬浮炮台。
  - Reik：红色双斧重装狂战士。
  - Olia：淡蓝时空装置与长外套。
  - Graf：紫色分段石甲、胸口混沌核心。
  - Liana：白色兜帽、冰晶狙击步枪。
- 战斗显示尺寸由 60px 提升到 82px。
- 移除角色背后的大圆形徽章，改为贴地扁椭圆接触阴影和身份色脚环。
- 根据鼠标方向水平翻转；移动时完全禁止缩放摆动，待机只使用 1.2% 的原地呼吸且不改变逻辑坐标，避免重新引入移动抖动。

### 3.3 后续动画生产规范

当前是单帧 Sprite 的最低成本升级。商业完成版应继续制作：

- idle：6～8 帧，1.2～1.8 秒循环。
- move：8 帧，脚步落点与音效同步。
- attack：前摇、武器爆发、后坐、恢复至少 4 段。
- hit：80～140ms，不覆盖操作响应。
- death：0.6～1.0 秒，禁止直接消失。
- Q/E/R：各有独立起手轮廓，Boss 战中也能辨认。

### 3.4 验收

- 64px 缩略图下不看颜色也能区分六名英雄。
- 角色武器方向与实际瞄准方向一致。
- 脚部接触地面，不出现漂浮或胸像滑动。
- 呼吸动画不移动世界坐标，录屏逐帧检查位置不得抖动。

## 4. 特效实机审查与重构

### 4.1 审查结论

旧 `fx_heal.png` 是不透明黑底上的写实绿色探照灯，治疗时会出现方形黑块，并且与俯视战斗不匹配。进一步检查发现：

| 资源 | 旧角落 Alpha | 旧问题 | 新处理 |
|---|---:|---|---|
| `fx_heal.png` | 黑底 | 写实光柱、十字符号、像舞台灯 | 薄六角治疗环、薄荷色上升能量、暖白核心 |
| `fx_explosion.png` | 58/255 | 黑色脏雾、写实火球 | 透明底、橙色冲击环、方向碎片 |
| `fx_cold_arrow.png` | 75/255 | 黑蓝方底、装饰雪花感 | 透明底、非对称冰片和冲击中心 |
| `fx_hex_ring.png` | 0 但周边偏黑 | 过曝静态标志 | 双层错位六角环、短电路火花 |
| `fx_poison.png` | 0 但整体像插画云 | 体积过大、遮挡目标 | 俯视毒液溅射、破损危险环 |

五张替换后四角 Alpha 均为 0；原文件名和 `.meta` 保持不变。

### 4.2 治疗反馈规则

- 正常回血：治疗法阵 0.5 秒，绿色上升粒子，暖白核心，绿色数值，播放治疗音。
- 攻击吸血：高频事件只显示小型绿色数值，不铺完整法阵，防止每颗子弹都遮挡玩家。
- 满血：实际回血小于 1 时不播放治疗效果和声音。
- 治疗色使用薄荷绿，不使用毒液的黄绿色。

### 4.3 通用特效层级

每个核心特效按三段式制作：

1. **前摇**：范围、方向和来源清晰；不造成伤害。
2. **爆发**：白热核心 + 类型主色 + 方向性碎片；高伤害可触发短 Hit-stop。
3. **收尾**：残留环、少量烟尘或碎片快速消散；不得留黑色方块。

危险信息不能只靠颜色：近战使用扇形/刃线，冲锋使用路径，范围技能使用闭合轮廓，追踪弹使用锁定刻度。

### 4.4 资源验收自动化

- 所有 VFX PNG 四角 Alpha 必须为 0。
- 在浅灰、深灰、章节背景三种底色上检查是否出现矩形边缘。
- 64px、96px 两档检查主体可读性。
- 同屏 20 个特效时，玩家轮廓仍必须完整可见。
- 已增加 `tests/specs/visualmanifest.test.js`：使用 Node 内置 zlib 解析 PNG，自动检查五张 VFX 与六名英雄的尺寸/透明四角、金币正式贴图，以及四章背景的 16:9 与最低分辨率。

## 5. 场景与镜头优化

- 背景改为“基础材质 + 裂纹/污渍 Decal + 边缘结构 + 局部故事物件”，不要继续直接铺完整 AI 海报。
- 中央 65% 战斗区亮度和纹理频率保持稳定；当前使用三层低透明度蓝黑遮罩逐级羽化，避免单块硬边矩形；最亮环境像素不得超过敌方预警核心。
- 每章共享相同的材质笔触和光照，仅替换主题色与边缘物件。
- 镜头震动按事件分级：普通命中 0、精英重击 1、Boss 重击 2、终极技能 3；不可叠加成持续抖动。
- 增加“震屏强度、关闭闪烁、特效密度”设置。

## 6. UI 系统后续优化

- HUD、商店、强化卡、角色选择统一使用 8px 间距网格。
- 标题/数字/正文使用三层字号，不允许所有文本都依赖厚描边。
- 角色锁定图标改为正式矢量/位图，不使用 Emoji。
- 商店商品增加真实图标、购买前后材质变化和余额不足反馈。
- 强化卡增加 hover 提升、选择确认闪光和稀有度专属边框动画。
- 首页背景最终应输出无按钮纯背景版本；当前深色操作台是兼容旧图的过渡方案。

## 7. 音乐音效策略

完整接线和音量表见 `docs/audio/audio-integration-2026-08-20.md`。

音频与画面必须同一帧级协作：攻击声在枪口爆发帧，命中声在伤害结算帧，Boss 警报必须早于伤害，拾取声随连续金币形成节奏但受并发限流。

## 10. 2026-08-20 实机反馈闭环补充

### 10.1 角色白框

- 六名 `char_token_*` 统一重新装入 512×512 透明画布，主体不接触图像边缘。
- 源图外沿至少 8px 的 Alpha 必须全部为 0；`.meta` 开启 `fixAlphaTransparencyArtifacts`，减少双线性采样把边缘残色带入 Sprite。
- 验收：六名角色逐一出战，在浅色和深色背景下移动、转向、受击，轮廓外不得出现白色矩形或硬边。

### 10.2 弹丸与武器发射

- 六职业各使用一张 256×128 定向透明弹体：Kai 轨道枪栓、Vivian 微型导弹、Reik 冲击斧刃、Olia 时空针、Graf 混沌长矛、Liana 冰晶狙击弹。
- 玩家、分身与炮台发射均必须携带 `charKey`；Sprite 保持原图白热核心、金属外壳和尾焰，不再整张染成角色纯色。
- 运行时按速度方向旋转，显示框保持横向比例；敌弹继续使用高对比程序化威胁形状，避免敌我混淆。

### 10.3 技能名称唯一出口

- Q/E 名称只允许 `PlayerController` 在技能成功触发后显示一次，`CharacterDB` 中的技能效果不得再次创建同名飘字。
- 薇薇安 E 的唯一名称固定为“网络连接”；“连接网络”不再出现在表现层。
- R 技能因各角色具有独立全屏演出，仍由各终极技能效果负责一次性标题显示。

### 10.4 敌人与炮台形状

- 普通怪和 Boss 取消常驻圆形底盘/描边，平时仅绘制低矮接触阴影；红橙危险圈只在实际攻击前摇存在。
- 薇薇安固定炮台和轨道炮台改为六角钢制底座、双联炮管、菱形能源舱，并实时朝目标转向；不得再以蓝色圆圈代替炮台。
- Graf 分身使用角形人形剪影，与机械炮台明确区分。

### 10.5 回归门禁

- PNG 门禁逐像素检查英雄 8px、弹丸 4px 的全透明外沿。
- Headless 渲染门禁检查炮台弹启用角色 Sprite、保持原色、横向比例并按方向旋转。
- 角色数据门禁检查六名英雄 Q/E 效果层都不含第二条 `floatingText` 路径。
