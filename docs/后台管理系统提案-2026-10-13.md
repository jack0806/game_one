# 后台管理系统提案（2026-10-13）—— 已实现

> 状态：**已实现（2026-10-13），待提交**。入口按玩家指示调整为：**首页/暂停 → 设置 → 「后台管理」按钮**（原版本号连点方案废弃）。
> 内含 **系统参数配置**（GameConfig 注册表 28 项）与 **成就管理**（分类 + 增加/编辑/下架成就）两大模块。
> 关联：成就数值重定档见《成就设计提案-2026-10-13.md》v4；成就管理的直接价值就是上线后**不用改代码就能调成就目标值**。

## 1. 管理员身份（已按此实现）

- **进入**：设置页「后台管理」按钮 → 首次弹出密码输入框（默认密码 `hex2026`，可在后台系统参数页底部修改）→ 验证通过写入 `localStorage['hexblast_admin_v1']`。
- **可见性**：入口按钮所有人可见，但内容被密码门拦住；验证通过后——
  - 后台面板直接进入功能页（本机记住管理员身份，免密进入）；
- **退出**：后台管理面板右上角「退出管理员」，清除标记，下次进入需重新输密码。

## 2. 总体架构

```
data/GameConfig.ts          系统参数注册表（27 项，第 3 节）
systems/AchievementAdmin.ts 成就管理数据层（覆盖/自建/分类，第 4 节）
ui/AdminUI.ts               后台管理面板（整页浮层，两个页签）
  ├─ 页签1 系统参数：滑条 + 恢复默认
  └─ 页签2 成就管理：分类树 + 成就列表 + 编辑表单
```

- 改动**即改即存**（写 localStorage，无保存按钮）；每项标注生效时机（局内即时 / 下局生效 / 结算时）。
- 全局作用域（不按存档槽隔离——后台是设备级调试/运营工具）。
- `GameConfig`/`AchievementAdmin` 均为纯 TS + 可注入 stub 的 localStorage，headless 可测；**测试房/mock 恒读默认值**，不受残留配置影响。

## 4. 页签2：成就管理

### 4.1 数据层（`AchievementAdmin`）

存储 `localStorage['hexblast_admin_achievements_v1']`：

```ts
{
  categories: ['挑战', '探索', '收集'],          // 可新增（名称 + 主题色）
  overrides: { [内置成就id]: { goal?, name?, desc?, rarity?, category?, reward?, rewardCoins?, hidden?, retired? } },
  custom: [ { id, name, desc, category, rarity, statField, goal, reward, rewardCoins?, hidden? } ],
}
```

- **生效列表 = 静态 ACHIEVEMENTS（套用 overrides）+ custom**；成就墙展示、局末判定、结算汇总都读合并列表。
- **内置成就**：可编辑（目标/文案/稀有度/分类/奖励/隐藏）、可**下架**（retired，不再展示与判定；已解锁记录保留）；**不可删除**（id 稳定，防存档悬空）。
- **自建成就**：可删除。
- 进度来源（自建成就从下拉选择，白名单）：`totalRuns / totalWins / totalKills / bossKills / chaptersCleared / bestWave / totalGoldEarned / bestCombo / bestAugmentCount / bestKillsInRun / charsPlayed数 / coreCoins / equipments数 / jokerDolls`——全部是 `PlayerProfile` 已有字段，不为自建成就改战斗内核。

### 4.2 面板交互

- **左侧**：分类列表（挑战/探索/收集/自建分类），每类显示"已解锁/总数"；底部「+ 新建分类」（名称 + 主题色）。
- **右侧**：该分类下成就列表——每行 名称 / 等级 / 目标 / 奖励 / 状态（启用·已改·下架），操作：编辑、下架/恢复、删除（仅自建）；顶部「+ 新增成就」。
- **编辑表单**（浮层内嵌）：名称、描述、分类下拉、稀有度下拉、目标值（数字）、进度来源下拉（仅自建）、奖励文案、核心币奖励、隐藏开关；保存即写入并即时生效。
- 成就墙页签 = 分类列表渲染（含自建分类），与后台共用一套分类数据。

### 4.3 与成就提案的衔接

- 成就提案 v4 的挑战重定档（累计击杀 30 万、首领 500 等）先按表落地为内置数据；
- 上线后你用成就管理**直接改目标值做实测校准**（尤其连击类"待实测校准"档位），不用再走代码改动。

## 5. 防呆与边界

- 数值钳制 min/max；非法输入回弹。
- `adminPassword` 为空时禁止进入后台（防误清）。
- 后台改动不回写静态数据文件（`SaveSystem.ts` 的 ACHIEVEMENTS 等），仅运行时覆盖——"恢复默认"随时可撤。
- 金币/难度系数调高会让成就变快：预期行为（设备级自用工具，无竞技环境）。
